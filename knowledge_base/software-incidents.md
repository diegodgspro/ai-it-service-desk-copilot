# Software: General incident

Portfolio knowledge article. Synthetic lab context; technician validation required.

## Symptoms
- desktop application crashes or will not launch
- software error after an approved update
- application freezes for one user
- general program installation or runtime failure

## Working hypothesis
A local application state, dependency, configuration, or recent approved change may be responsible.

## Troubleshooting
1. Capture the exact error, application version, start time, and affected scope.
2. Confirm whether the same approved application works for another synthetic user or workstation.
3. Review recent approved changes and vendor support status without downloading unapproved tools.
4. Preserve user files and logs approved for support before proposing repair or reinstallation.
5. Validate recovery with the user; escalate repeat crashes, security indicators, or unsupported software.

## Escalation and closure
Escalate when scope exceeds authorization, symptoms persist, or security indicators appear. Close only after user validation. Record evidence and outcome.
